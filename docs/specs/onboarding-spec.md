# 듀(Due) — 온보딩 & 첫 프로젝트 생성 기능 스펙

> 출처: Figma `2026 MVP 런칭` → 섹션 **`온보딩 Draft-3차 수정`** (node `233:474`)
> 이 문서는 LLM이 기능을 빠르게 파악하도록 **화면(Screen) → 상태(State) → 데이터(Data)** 순으로 정규화한 것이다.
> 화면 안의 한국어 카피는 디자인 원문을 그대로 인용한다. `{...}`는 동적 바인딩 값이다.

---

## 0. 제품 한 줄 요약

**듀(Due)** 는 커플/파트너가 **함께** 큰 인생 프로젝트(결혼식, 내 집 마련, 신혼여행 등)를 계획하고 실행하는 협업 앱이다.
사용자가 목표만 입력하면 **AI가 단계별 계획(할 일 목록 + 일정)을 자동 생성**하고, 파트너를 초대해 역할을 나눠 진행한다.

### 핵심 도메인 용어 (반드시 이 의미로 사용)

| 용어 | 의미 | 비고 |
|---|---|---|
| **프로젝트(Project)** | 사용자가 준비하는 하나의 큰 목표 | 예: 결혼식, 내 집 마련 |
| **듀(Due)** | 프로젝트를 구성하는 **단계/페이즈(Phase)** | "듀 1: 큰 결정", "듀 2: 세부 기획 & 예약" … 앱 이름과 같은 단어로 의도된 워드플레이 |
| **항목(Item / 할 일 / subtask)** | 하나의 듀 안에 속한 개별 태스크 | 예: "날짜 확정", "예산 범위 확정" |
| **담당(Assignee)** | 항목을 수행하는 주체 | `{name}(나)` / `파트너` / `함께` / `미배정` |

> 데이터 계층: **Project → Due(Phase) → Item(subtask) → Assignee**

## 1. 전체 플로우 (Figma 주석 라벨 = 정식 단계명)

Figma 보드 상단의 단계 라벨(`온보딩`, `첫 프로젝트 시작` …)이 이 플로우의 공식 골격이다.

```
[온보딩]
  S1 스플래시/온보딩 캐러셀
  S2 소셜 로그인 (외부 채널 약관 동의)
        │
[첫 프로젝트 시작]
  S3 프로젝트 종류 선택 (결혼식 / 내 집 마련 / … / 나만의 프로젝트)
  S4 닉네임 입력
        │
[날짜 선택 기본] [준비 스타일 선택] [추가 고려사항 입력]  ← 정보 입력 단계 (한 화면에 묶여 있음)
  S5 프로젝트 정보 입력  (일정 + 준비 스타일 + 추가 고려사항)
        │
  S6 계획 수준 선택 ("어디까지 계획을 세워드릴까요?")
  S7 AI 생성 로딩
        │
[세부 일정 조정]
  S8 환영 + 계획 완성 안내 캐러셀
  S9 계획 검토/수정 (생성된 듀·항목 확인)
        │
[초대 및 역할 분담]
  S10 파트너 초대
  S11 내 프로필 완성
  S12 할 일 배정
        │
[완료/프로젝트 시작]
  S13 홈/대시보드 진입
        │
[프로젝트 편집]  ← S9 및 홈에서 진입하는 편집 모드 (별도 단계)
  S14 프로젝트 수정 / 듀·항목 추가·삭제 / 색상·메모 편집
```

> **분기**: `결혼식`(MVP 메인) vs `나만의 프로젝트`(자유 입력형)는 S3·S5의 카피와 입력 방식이 다르다. 잠금(🔒) 프로젝트는 MVP에서 비활성.

## 2. 화면별 상세 스펙

### S1. 스플래시 / 온보딩 캐러셀
- **목적**: 앱 가치 제안 소개.
- **요소**: 로고 카피 `Stay in Due.`, 하단 `다음`(next) / `건너뛰기`(skip).
- **슬라이드 카피(순서대로)**:
  1. `파트너와 함께하는\n새로운 시작을 더 쉽게`
  2. `시간이 부족하고 \n어디부터 시작해야할지 막막할 때`
  3. `계획을 세우는 것 부터,\n실행까지 듀에서 한 번에`

### S2. 소셜 로그인 (외부 채널 약관 동의)
- **헤드라인**: `Stay in Due.` / `함께하는 계획, \n듀에서 더 빠르고 쉽게`
- **로그인 버튼**: `카카오로 시작하기`(보조문구 `3초만에 빠른 회원가입`), `네이버로 시작하기`, `구글로 시작하기`, `Apple로 시작하기`
- **백엔드 연관**: 현재 코드베이스에 카카오 OAuth 존재. 네이버/구글/Apple은 디자인상 노출.

### S3. 프로젝트 종류 선택
- **헤드라인**: `준비하려는\n프로젝트를 선택해보세요` / 보조 `듀가 단계별 계획을 만들어드릴게요.`
- **카드 목록** (🔒 = MVP 잠금/비활성):
  - `결혼식` ✅ (MVP 활성, 기본 시나리오)
  - `내 집 마련` 🔒, `신혼 여행` 🔒, `자녀 계획` 🔒, `운동` 🔒
  - `나만의\n프로젝트` (자유 입력형, 별도 분기)

### S4. 닉네임 입력
- **헤드라인**: `반가워요!\n어떻게 불러드릴까요?` / 보조 `사용할 닉네임을 입력해주세요.`
- 한글 키보드 + CTA `이 닉네임 사용하기`. 이후 화면에서 `{name}`으로 바인딩.

### S5. 프로젝트 정보 입력  ★핵심 입력 화면
> 단계 라벨 `날짜 선택 기본` + `준비 스타일 선택` + `추가 고려사항 입력`이 하나의 스크롤 화면에 묶여 있음.

- **타이틀**: `결혼식 정보 입력` / 보조 `날짜와 추가 고려사항을 입력해주세요.` (변형: `결혼식 날짜, 시간, 예산, 장소를 입력해주세요`)
- **필드 1 — 일정(날짜)**:
  - 미입력 placeholder `날짜를 선택해주세요.` → 선택 후 `2026년 1월 11일`
  - **날짜 피커 모달**: 토글 `날짜 지정` ↔ `유연한 일정`, 연/월 캘린더, `확인`
- **필드 2 — 준비 스타일** (택1, `?` 도움말 제공):
  - `🥊 할 수 있는 것 다 하기` / `💵 지갑 지키기` (라벨 변형: `제대로 하기` / `내 지갑 지키기`)
  - 도움말 툴팁: `어떤 스타일을 선택해야할지 모르겠다면 → "🥊 할 수 있는 것 다 하기"를 선택하고, 제외할 항목들을 나중에 편집해보세요.`
- **필드 3 — 추가 고려사항** (자유 텍스트, `?` 도움말):
  - placeholder: `계획을 짤 때, 참고하면 좋을 것들이 있다면 자유롭게 작성해주세요. 작성된 내용을 기반으로 최적의 일정을 짜드릴게요.`
  - 예시 입력: `예물, 예단은 안할거예요. DVD랑 아이폰 스냅은 꼭 하고싶어요. 웨딩 베뉴는 ""로 결정했어요.`
  - 권장 작성 예시(가이드): `- 예물·예단은 간단하게 하거나 생략할 예정이에요. / - DVD 촬영이나 아이폰 스냅은 꼭 하고 싶어요. / - 웨딩 베뉴는 OO로 이미 결정했어요.`
- **CTA**: `계획 세우기` (변형: `완료`, `모두 적었어요.`)

#### S5-alt. 나만의 프로젝트 (자유 입력형)
- 헤드라인: `어떤 것을 준비하시나요?\n간단한 정보를 입력하고 계획을 세워보세요`
- placeholder: `준비하는 프로젝트의 대략적인 목표 일정, 예산, 진행 상황 등을 자유롭게 적어주세요.`
- 예시: `어버이날 기념, 부모님 모시고 가족 여행 갈거야. 올해 5월 주말 중에 가고싶어.`
- 준비 스타일(자유형 카피): `🥊 할 수 있는 것 다 할래요` / `💵 돈을 최대한 절약하고 싶어요` / `🧐 잘 모르겠어요, 추천대로 할래요`
- CTA: `입력하기` / `다음에 하기` / `뒤로 가기`

### S6. 계획 수준 선택 (AI 생성 옵션)
- **헤드라인**: `시작이 반!\n어디까지 계획을 세워드릴까요?`
- **옵션(택1)**:
  - `📝 꼼꼼하게 만들어주세요` (상세 자동 생성)
  - `🗒️ 우선 큰 틀만 만들게요` (듀/페이즈만 생성)
  - `✍🏻 제가 직접 하나씩 계획을 세울래요` (빈 계획 + 수동)
- CTA: `새 프로젝트 만들기` / `뒤로 가기`

### S7. AI 생성 로딩
- 헤드라인: `잠시만 기다려주세요\n해야 할 일을 정리하고 있어요`
- 진행 카피(순차): `입력해주신 내용을 읽어보고 있어요` → `할 일 목록 생성 중...` → `최적의 일정 계산 중...`

### S8. 환영 + 계획 완성 안내 캐러셀
- `{name}님,\n만나서 반가워요!`
- `모든 준비가 끝났어요!`
- 안내 슬라이드:
  - `체계적으로 준비할 수 있게\n단계별 계획을 완성했어요`
  - `세부 일정을 조정해보세요, 제 때 해야할 일들을 듀가 챙겨드릴게요.`
  - `파트너와 역할을 나누고\n진행상황을 공유해보세요`

### S9. 계획 검토 / 수정
- **헤드라인**: `{pj name} 듀가 완성됐어요!` (예: `결혼식 듀가 완성됐어요!`) / 보조 `단계별로 확인하고, 계획을 수정해보세요.`
- 요약 헤더: `{프로젝트} N개월 계획`, `{yyyy년 mm월 dd일}`, `D-{N}`(예 `D-324`), `할 일 {Count}개`
- 듀 카드 = `듀 {n}` + 페이즈명 + `D-{N}` + `{n}개 항목` (펼치면 항목 리스트)
- CTA: `수정하기` → S14 / `이대로 시작하기` → S10
- 안심 카피: `걱정마세요, 시작한 후에도 계획을 변경할 수 있어요`

### S10. 파트너 초대
- 헤드라인: `함께할 파트너를\n초대해보세요`
- 초대 메시지 미리보기: `우리 {프로젝트} 계획 세워봤어. \n같이 해보자! 🎉` + `위 메시지로 초대장이 전송됩니다`
- 가치 제안 `함께하면 좋은 점`: `역할을 나누어 효율적으로 준비해요` / `실시간으로 진행 상황을 공유해요` / `완료한 일을 서로 확인하고 응원해요`
- CTA: `초대하기` / `건너뛰기`
- 대안 진입: `상대방 코드로 연결하기` / `다음에 초대하기`

### S11. 내 프로필 완성
- 헤드라인: `파트너를 초대하기 전,\n내 프로필을 먼저 완성해보세요` (대기 변형: `기다리면서\n내 프로필을 완성해보세요`)
- 아바타: `아이콘 생성` / `내 사진으로 만들기`
- 필드: `이름`(예: `서노`)
- CTA: `저장하고 계속` / `건너뛰기`

### S12. 할 일 배정
- 헤드라인: `할 일 배정하기` / 보조 `각각의 항목을 누가 할지 지정해주세요.`
- 각 항목에 담당 칩 부여: `{name}` / `파트너` / `함께` (기본 `미배정`)
- CTA: `건너뛰기`
- 빈 상태: `아직 할 일이 배정되지 않았어요! 각자 해야할 일들을 정해보세요.` → `지금 배정하기`

### S13. 홈 / 대시보드 (완료/프로젝트 시작)
- **하단 탭**: `프로젝트` / `캘린더` / `Todo` / `마이`
- **프로젝트 목록 카드**: 종류명 + `D-{N}` + 진행률(`0%`, `24%` …), 잠금 프로젝트는 🔒
- **진행 상황 요약 카드**: `{프로젝트} 준비 진행 상황`, 상태 집계 `16 완료 / 4 진행중 / 4 진행 전`, `24%`, `D-324`
- **빠르게 해야 할 일**: `{name}` + 기한(`오늘까지`/`내일까지`/`5월 12일까지`) + `{subtask}를 완료해야해요.`
- **보기 옵션(필터/그룹)**: 그룹 `역할별` ↔ `듀 별`, 필터 `할 일` ↔ `일정`
- 역할별 그룹: `함께 할 일`, `{name} 할 일`, 각 그룹 `{n}개 항목` + 진행 `4/6` 형태
- 빈 상태: `아직 배정되지 않았어요!` / `할 일이 배정되지 않았어요!`

### S14. 프로젝트 편집 / 듀·항목 관리
- 헤드라인: `프로젝트 수정하기` / 보조 `하지 않을 일정을 삭제하거나, 수정해주세요.` (또는 `{pj name} 계획을 시작해보세요 / 단계별로 할일을 추가해보세요.`)
- 메타 필드: `프로젝트 명`(예 `결혼식`), `일정`(`2026년 1월 11일`), `색상 선택하기`
- 듀(페이즈) 표기: `듀 {n}` 또는 기간형 `Week 1-2`, `Week 3-4` … / 항목별 `D-{N}`
- 조작: `새로운 항목 추가하기`, `Due 추가하기`, `선택 항목 모두 삭제하기`
- CTA: `취소` / `확인` / `이대로 시작하기`
- **듀(카테고리) 수정 모달**: `카테고리 명`(=Due 타이틀), `날짜`/기간(`캘린더 표기 시 외부에서는 D-day로 표기`), 진행상태 `진행중`/`진행전`, 담당(`함께`/`서노`/`민수`), `메모를 입력하세요`, `색상 선택하기`(Phase 추가 시 색상), `저장`
- **초기화(다시 시작)**: `만들던 프로젝트를 초기화하고\n처음부터 다시 시작할까요?` → `새로 만들기` / `계속 편집하기`

## 3. 데이터 모델 — 기획 vs 실제 구현 대조

> ✅ = 코드에 구현됨 · ⚠️ = 일부만/이름 다름 · ❌ = 기획에만 있고 코드에 없음
> 실제 엔티티: `src/{projects,phases,tasks,users}/entities/*.entity.ts`
> **명명 매핑**: 기획 "듀(Due/페이즈)" = 코드 **`Phase`**, 기획 "항목/할 일" = 코드 **`Task`**.

### 3.1 실제 엔티티 (현재 코드 기준)

```
Project (projects)                              # id: number (auto-increment)
├─ ✅ projectName : varchar                      # 자유 문자열 (종류 enum 아님)
├─ ✅ startDate   : date (필수)                  # 유연한 일정 미지원
├─ ✅ dueDate     : date (필수)                  # 목표일. D-day는 파생값(미저장)

├─ ✅ personality : jsonb { preparationStyle: string, additionalConsiderations: string }
├─ ✅ owner       : ManyToOne(User)  onDelete CASCADE
└─ ✅ phases      : OneToMany(Phase)

Phase (phases)  =  기획의 "듀/페이즈"           # id: number
├─ ✅ name             : varchar                 # "큰 결정", "세부 기획 & 예약" …
├─ ✅ expectedStartDate: date
├─ ✅ expectedEndDate  : date
├─ ✅ order            : int
├─ ✅ project          : ManyToOne(Project) CASCADE
└─ ✅ tasks            : OneToMany(Task)

Task (tasks)  =  기획의 "항목/할 일"            # id: number
├─ ✅ name   : varchar
├─ ✅ status : enum TaskStatus { TODO, IN_PROGRESS, DONE }   # 기획 진행전/진행중/완료에 매핑
├─ ✅ order  : int
└─ ✅ phase  : ManyToOne(Phase) CASCADE

User (users)                                    # id: uuid
├─ ✅ authProvider   : 'kakao' | 'google' | 'apple'   # ⚠️ naver 없음
├─ ✅ oauthSub       : varchar (ID Token sub)
├─ ✅ nickname       : varchar | null
├─ ✅ email          : varchar | null
├─ ✅ profileImageUrl: varchar | null
└─ ✅ refreshToken   : varchar | null
```

## 6. 컴포넌트 상태 정의 (Figma 보조 섹션)

- **입력칸 Status**: `현재 입력값`(채워진 값, 예 `김듀듀`) / `입력 중`(커서 `|` 표시) — 입력 필드 3종 상태.

- **빈 상태(Empty)**: `아무것도 배정되지 않았을 때` → `할 일이 배정되지 않았어요!` / `아직 배정되지 않았어요!`.
- **Due 색상**: `Phase 추가 시 색상` 팔레트에서 듀별 대표 색 지정.

| S6/S9 생성 | `POST /projects` | 클라가 phases[]까지 통째로 전송해 일괄 저장(트랜잭션) |

| S2 | 네이버 로그인 | ❌ provider enum에 naver 없음 |

| S9/S13 | 프로젝트 **단건 조회** `GET /projects/:id` | ❌ 목록만 존재 |

| S14 | 항목(Task) **추가/삭제** | ❌ status/order PATCH만, 생성·삭제는 `POST /projects` 일괄뿐 |
| S14 | Phase `name/memo/color/기간` 수정 | ❌ Phase는 order만 수정 가능 |
| S10 | 파트너 **초대/코드 연결** | ❌ 협업 도메인 자체 없음 |
| S12 | 항목 **담당 배정** `PATCH /tasks/:id { assignee }` | ❌ assignee 컬럼 없음 |
| S11 | 아바타 **생성/업로드** | ❌ |
| S14 | 프로젝트 **초기화**(다시 시작) / **삭제** | ❌ |

### 7.3 정합성 메모 (기획 ↔ 코드가 어긋나는 지점)

- **budget**: 코드는 `budget`을 **필수**로 받지만, S5 입력 화면엔 예산 필드가 명시적으로 보이지 않음 → 기획에 예산 입력 UI 추가 또는 코드에서 optional 처리 결정 필요.
- **suggest 입력 비대칭**: `POST /projects/suggest`는 `dueDate`만 받고 `startDate/projectName/budget`는 응답에만 존재. S5는 일정·스타일·고려사항을 함께 입력하는데 projectName(종류)이 suggest 입력에 빠져 있어 AI가 종류를 모름 → 종류/시작일 입력 전달 보강 검토.
- **personality vs style**: 기획의 정해진 enum(🥊/💵/🧐)을 코드는 자유 string으로 저장 → 값 표준화(상수화) 권장.

## 8. LLM 작업 시 주의점

1. **"듀"는 두 가지 의미**: ① 앱 이름(Due) ② 프로젝트의 단계/페이즈. 문맥으로 구분할 것. 항목 수정 모달은 "카테고리"라고도 부름(=Due 타이틀).
2. **MVP 범위**: `결혼식`만 활성. 나머지 4종은 🔒 비활성이지만 데이터 구조·워딩시트는 준비되어 있음(향후 확장).
3. **분기 2종**: 정형(결혼식 등 종류 선택형) vs `나만의 프로젝트`(자유 입력형) — 입력 화면 카피·필드가 다름.
4. **AI 생성 옵션(planLevel)** 에 따라 생성 깊이가 달라짐: 상세 / 큰 틀만 / 수동.
5. 모든 `건너뛰기` 가능 단계(초대·프로필·배정)는 **선택**이며, 스킵해도 홈(S13)에 도달함.
